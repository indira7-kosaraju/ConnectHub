# Deploying ConnectHub

Production layout (all free tiers):

| Piece | Host | Notes |
| --- | --- | --- |
| Database | **Neon** (PostgreSQL 16) | Plain JDBC connection; Flyway migrates on startup |
| API | **Render** (Docker web service) | `server/Dockerfile`, health check `/actuator/health` |
| Website | **Vercel** (static Vite build) | `client/`; `vercel.json` proxies `/api`, `/oauth2`, `/login/oauth2`, `/uploads` to Render |
| Images | **Cloudinary** | Required in production (Render's disk is wiped on every deploy) |

The browser talks to **one origin** (your Vercel domain) for everything except the WebSocket,
so the refresh-token cookie stays first-party (see DECISIONS #19). The WebSocket connects
straight to Render and authenticates with the JWT.

> Order matters: **Neon → Render → Vercel → back to Render** (once you know the Vercel URL) **→ Google (optional)**.
> Never paste secrets into code, chat or commits. They go only into each dashboard's environment settings.

---

## 0. Push the code to GitHub

```bash
cd ConnectHub
git init -b main && git add . && git commit -m "ConnectHub"
gh repo create connecthub --private --source . --push     # or create the repo on github.com and `git push`
```

CI (`.github/workflows/ci.yml`) runs on every push: server tests (JUnit + Testcontainers), client build,
then Playwright end-to-end tests against a real API.

## 1. Database: Neon

1. neon.tech → **New project** → Postgres **16**, region close to your Render region (e.g. AWS us-west-2 for Render Oregon).
2. **Connection details** → choose the **direct** connection (not the `-pooler` host) → copy host, database, user, password.
3. Turn the URL into JDBC form; you'll need these three values for Render:

   ```
   DATABASE_URL      = jdbc:postgresql://<host>/<database>?sslmode=require
   DATABASE_USERNAME = <user>
   DATABASE_PASSWORD = <password>
   ```

   Example host: `ep-cool-sun-123456.us-west-2.aws.neon.tech`. Don't include `user:password@` in the URL.

## 2. Images: Cloudinary

cloudinary.com → **Dashboard** → copy **Cloud name**, **API Key**, **API Secret**.

## 3. API: Render

1. render.com → **New → Blueprint** → connect your GitHub repo. Render reads `render.yaml`.
2. It creates **connecthub-api** (Docker, free plan, health check `/actuator/health`) and asks for the `sync: false` values:

   | Key | Value |
   | --- | --- |
   | `DATABASE_URL` / `DATABASE_USERNAME` / `DATABASE_PASSWORD` | From step 1 |
   | `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | From step 2 |
   | `FRONTEND_URL`, `CORS_ALLOWED_ORIGINS` | Put `https://example.com` for now and fix them in step 5 |
   | `GOOGLE_*` | Leave empty unless you set up Google sign-in (step 6) |

   `JWT_SECRET` is generated by Render automatically. `SPRING_PROFILES_ACTIVE=prod,demo` loads the demo
   content (20 users, all with password `Password123`). Change it to `prod` when you don't want demo data.
3. Wait for the deploy, then open `https://<service>.onrender.com/actuator/health` → `{"status":"UP"}`
   and `https://<service>.onrender.com/swagger-ui.html`.

   Note the exact service URL. If `connecthub-api` was taken, Render adds a suffix.

## 4. Website: Vercel

1. **Point the proxy at your API.** In `client/vercel.json`, replace every
   `https://connecthub-api.onrender.com` with your Render URL from step 3. Commit and push.
2. vercel.com → **Add New → Project** → import the repo:
   - **Root Directory:** `client`
   - Framework preset: **Vite** (build `npm run build`, output `dist`)
   - **Environment Variables:**

     | Key | Value |
     | --- | --- |
     | `VITE_API_URL` | *(leave empty: same-origin through the rewrites)* |
     | `VITE_WS_URL` | `https://<your-render-service>.onrender.com/ws` |
3. Deploy, then note your production URL, e.g. `https://connecthub-xyz.vercel.app`.

## 5. Connect them (back to Render)

Render → connecthub-api → **Environment**:

| Key | Value |
| --- | --- |
| `FRONTEND_URL` | `https://connecthub-xyz.vercel.app` |
| `CORS_ALLOWED_ORIGINS` | `https://connecthub-xyz.vercel.app` (add preview domains comma-separated, e.g. `https://connecthub-*-you.vercel.app`) |

Save. Render redeploys. Then open your Vercel URL, sign in as `maya@connecthub.dev` / `Password123`, and check:

- the feed loads, you can post with a photo (it uploads to Cloudinary), and vibes work;
- **Messages**: open a chat in two browsers and see live delivery and typing (this proves the WebSocket and CORS);
- `https://<render>/swagger-ui.html` loads.

## 6. Google sign-in (optional)

1. console.cloud.google.com → APIs & Services → **OAuth consent screen** (External, add yourself as a test user)
   → **Credentials → Create OAuth client ID → Web application**.
2. **Authorized redirect URI:** `https://connecthub-xyz.vercel.app/login/oauth2/code/google`
3. Render → Environment: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
   `GOOGLE_REDIRECT_URI=https://connecthub-xyz.vercel.app/login/oauth2/code/google`. Save, then redeploy.

The "Continue with Google" button appears automatically once both credentials are set.

## Operations notes

- **Cold starts:** Render's free plan sleeps after ~15 minutes idle; the first request then takes ~30–60 s.
  The SPA shows its splash and retries, but for demos open the API URL a minute beforehand
  (or use a paid instance).
- **Memory:** the image caps the heap at 60% of the container (`-XX:MaxRAMPercentage=60`) to fit 512 MB.
- **Scaling beyond one instance** needs a shared rate-limit store, a shared OAuth-state store and an
  external STOMP broker (see DECISIONS #27, #105).
- **Migrations** run automatically on startup (Flyway). Never edit an applied `V*.sql`; add a new version.
- **Secrets rotation:** changing `JWT_SECRET` signs everyone out (access tokens become invalid; refresh
  tokens still work and mint new access tokens).
- **Lighthouse:** run against the Vercel URL on mobile emulation (Chrome DevTools → Lighthouse, or
  `npx lighthouse https://… --preset=perf`). See README → Performance.
